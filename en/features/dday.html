Feature 02

D-Day

To the right of the usage cards, upcoming holidays · events · your calendar stand as dots on a time axis. Today is at the top, and the nearer a day is the more room it gets. When the dots crowd the top, you're about to be busy — the shape says so before you read a word.

The screen // dots on a time axis, beside the cards

The vertical line on the left of the sidebar is time. Today is at the top; the ticks read Today · 1 week · 1 month · 3 months. The axis is non-linear: the coming week takes half the screen and three months out folds into a few pixels. Each day is one dot on the axis, and the dot's shape is its category — ● holiday · ○ event · ★ my calendar. The card column does not move by a single pixel.

The toggle, the › button and "See all ›" really work. Same gestures as the app — the cards stay put, only the sidebar changes.

  • Shape is the category — ● holiday (filled) · ○ event (ring) · ★ my calendar. Because shape does that job, colour is spent in exactly one place.
  • Colour only for today and tomorrow — the D-n of today and tomorrow, the today marker, and the break bridge below are light blue. The green-to-red ramp of the usage gauges never appears in the sidebar: D-Day is not a warning.
  • Type the size of the cards — names and D-n are the same size as the percent figures on the cards next door, so they read from the same distance; the trade-off is about six items on screen at once. The date and time on the second line are small.
  • Tags — sub (substitute holiday) and temp (one-off holiday) have a solid border; tentative (not yet confirmed) is dashed.

Reading the timeline // the near future is wide

An item is two lines. The first is the name and D-n; the second is the date (and the time, for your own calendar). When two days sit so close their text would overlap, the later one is pushed down so nothing is covered — so a dot's vertical position means "around then", and the second line gives the exact date.

Events are folded. The dots on the default screen are holidays and your calendar; events gather into a single ○ at the position of the nearest one — "Events 4" plus the names of the closest two or three are visible at a glance, and the rest are one tap away behind "See all ›".

The break bridge. When only one to three workdays separate two holidays and bridging them with leave gives you five or more days off in a row, the axis between the two dots thickens and a line appears underneath: Leave 10/6–8 → 9 days off. DASH did the arithmetic; you only decide.

  • The "···" line — anything past three months folds into one line naming the next two items and their D-n.
  • When space runs out — items that don't fit on the axis go into the "···" line, starting with the category you placed lowest in Settings › Category order and the farthest dates first. The list always shows everything.

Open schedule // the same ticks become section headers

Tap "See all ›" and the axis disappears; the same ticks — Today · Tomorrow / 1 week / 1 month / 3 months / Later — become section headers, and all three categories interleave by date in one list. There's no limit on items, and it scrolls inside the sidebar only; the card column stays where it is. The fade at the bottom means "more below", and ‹ in the header takes you back to the timeline.

The "Schedule" toggle in the demo above is this screen. The long-press menu described further down lives here.

Tap // the detail card, and adding to your calendar

Tap a holiday dot or an event row in the schedule list and a detail card opens inside the sidebar: category and country, name and D-n, the date range, and two buttons — Add to Calendar and Close. Tap one of your own calendar items (★) and, instead of a card, the event opens in the operating system's own event screen (Apple's event view on iOS, the Calendar app on Android) — never a private URL scheme.

Add to CalendarClose

The detail card that opens when you tap a holiday or event. The light-blue button is "Add to Calendar".

  • Add to Calendar opens the operating system's event editor with the title and dates already filled in. Pick which calendar it goes into and tap Save — that's it. If you don't tap Save, nothing is created; DASH never writes an event on its own.
  • Permission, once. The first time you add something, the system asks whether to allow calendar access. On iOS this is an add-only permission, so even if you haven't connected your calendar in Settings, DASH can add without reading any existing events. If you already connected your calendar, you aren't asked again.
  • Tapping a calendar item → the operating system's own event screen (Apple's event view on iOS, the Calendar app on Android). Editing or deleting happens there, the same way as in the Calendar app.
  • Tapping the card column on the left does nothing to the sidebar. The sidebar is operated only from inside itself.

Long-press // 👍 Useful · 👎 Not for me · turn off an interest

In the schedule list only, after tapping See all ›, long-press an ○ event row. The menu always has 👍 Useful and 👎 Not for me, plus one Turn off … item (for example Turn off Festivals) for each active interest chip that also tags that event. Common events with no interest tag show only the two votes. Holiday and ★ calendar rows have no menu.

"Fireworks festival" held down. The third line names whichever interest that event belongs to.

  • 👍 Useful — one vote saying "glad I was told about this day".
  • 👎 Not for me — one vote saying "this has nothing to do with me".
  • Turn off Festivals — switches off the interest that event belongs to ("Festivals" here). An event tagged only with that interest disappears; one with another active interest stays. You can switch it back on in Settings any time.
  • One device sends each 👍/👎 vote once per event. Pressing the same vote again does nothing; turning an interest off is not limited this way.

Reactions are always anonymous. Exactly five things go to the server — event ID · reaction (👍 / 👎 / off) · country code · platform (iOS / Android) · app version.

  • No account, e-mail, name, device ID, advertising ID or install ID — nothing that could say who you are goes along. Not even the developer can tell which reaction came from whom.
  • Reactions are used only as aggregate input for deciding which kinds of events to show more or less. They are never used to target you with ads or to build a profile of you.
  • There's no switch to turn it on or off, because anonymity is a rule, not a setting. If you don't react, nothing is sent.
  • Holidays, your calendar items, and nothing whatsoever from your calendar ever go to the server. The details are in the Privacy Policy.

Interests // asked once on first open, changeable any time

The first time you expand the sidebar it asks one thing — "What events are you interested in?" Pick any number of the seven chips Festivals · Workers · Undergrad · Grad school · Job seekers · Dating · Other and tap Start. The question is "what interests you", not "who are you": you can be a worker and a job seeker at once, and a grad student can switch on dating events.

Holidays and your calendar are never asked about. They always show. Nationwide fun days that belong to no chip — Pepero Day, April Fools', Halloween — always show too. Your choice is stored on this device only and never sent anywhere.

The chips really toggle. They are the same seven switches as Settings › D-Day › Interests in the app.

  • Pre-selected chip — if at least one AI tool account is connected, "Workers" starts switched on. It's only a suggestion; turn it off if it's wrong. That guess is made on the device too.
  • Changing later — the toggles under Settings › D-Day › Interests, or long-press an event in the list and choose Turn off ….
  • You can pick nothing. You get a sidebar with holidays, your calendar and the common events only.

Event reactions (👍/👎) are always anonymous. No account or device identifiers are ever collected.
  • Region — Auto follows the device's region setting. Choose another country and the holidays and events switch to that country's; switch back and they're there instantly. The choices are the countries on the list.
  • Calendar access — this is where read access to your calendar is requested. Allow it and the upcoming events from every account on the device appear as ★. It is read-only and never leaves the device. If you decline, holidays and events still show. You can revoke it any time in the system settings (iOS: Settings › Privacy & Security › Calendars · Android: Settings › Apps › DASH › Permissions).
  • See your calendar as ★ · Allow — if calendar access has not been granted, this one-line row appears at the bottom of the sidebar. Tap Allow to ask iOS for read access; if access was denied earlier, the button opens system Settings.
  • Category order — change with ↑↓, the same way as the usage card order. It only decides which category folds into the "···" line first when the timeline overflows; the list is unaffected (always by date). A setting that works only where you can't see it.
  • Interests — the same seven switches as the chips on first open.
  • Refresh — the holiday and event list is checked once a day, and only a few KB are downloaded on days it changed. Offline, the last downloaded list (initially the current year's list bundled with the app) keeps working.

Collapse // the rail shows one ‹

Tap › in the header and the sidebar folds into a narrow rail that shows a single ‹ — no D-n, no dots. The card column widens by the same amount, so the gauge bars get longer. Tap the rail's ‹ to expand again; the collapsed state is remembered.

On days you don't need D-Day, leave it collapsed and the screen is exactly what it used to be. Try the › button in the demo above.
